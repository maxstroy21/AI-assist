# Second Brain Agent — персональный локальный AI-ассистент

Полностью локальный AI-ассистент: «операционная система знаний» одного человека.
Знает ваши документы, помнит контекст, управляет задачами и напоминаниями,
доступен через Telegram и локальные интерфейсы, работает на локальной LLM.

> Этот репозиторий сейчас находится на стадии **архитектурного проектирования**.
> Код появится только после согласования архитектуры (см. принцип «сначала
> проектирование, потом реализация»).

---

## Принципы

| # | Принцип | Что это значит на практике |
|---|---------|----------------------------|
| 1 | **Local First** | Все данные и вычисления — на вашей машине. Облако — опциональный плагин, а не зависимость. |
| 2 | **AI First** | Решения принимает LLM через tool calling. Мы не пишем «умную» бизнес-логику там, где её может выполнить модель. |
| 3 | **Modular** | Каждая способность — отдельный модуль, который можно включить/выключить в конфиге. |
| 4 | **Expandable** | Новые инструменты, источники данных, модели, агенты и каналы общения добавляются без переписывания ядра. |
| 5 | **Agentic** | Ассистент сам выбирает инструменты и планирует шаги, а не просто отвечает текстом. |

## Ключевые архитектурные решения (кратко)

| Область | Решение | Почему (подробно — в документах) |
|---------|---------|----------------------------------|
| Общая архитектура | **Модульный монолит** с внутренней событийной шиной и плагинами | Один процесс проще эксплуатировать на личной машине; модульность даёт расширяемость микросервисов без их операционной цены |
| LLM | Любой рантайм через **OpenAI-совместимый API** (Ollama, LM Studio, llama.cpp-server, vLLM, Jan…) | Рантайм — строка в конфиге, не архитектурное решение |
| Векторное хранилище | **Qdrant** (локальный, embedded-режим для старта) | Гибридный поиск, фильтры по метаданным, снапшоты; сравнение 6 вариантов — в [docs/02-architecture.md](docs/02-architecture.md) |
| Реляционные данные | **SQLite (WAL)** — задачи, память, метаданные, журнал | Нулевая эксплуатация, простой бэкап, достаточно для одного пользователя |
| Инструменты | Единый **Tool Registry** + **MCP** как протокол подключения внешних инструментов | Внутренние тулзы — in-process; внешние и сторонние — через MCP |
| Telegram | **aiogram 3**, long polling | Не нужен публичный IP — соответствует Local First |
| Голос | **faster-whisper** локально | Транскрипция голосовых без облака |
| Планировщик | **APScheduler** + SQLite job store | Переживает перезапуски, лёгкий |
| Язык/стек | Python 3.12, asyncio, Pydantic v2 | Экосистема AI-инструментов, типизация контрактов |

## Напоминания (Sprint 6)

Ассистент теперь сам пишет вам вовремя — в Telegram и в консоль:

- «Напомни завтра в 15:00 позвонить Ивану» → в 15:00 придёт сообщение
  с кнопками **✅ Сделал / ⏰ Позже / ✖ Отменить**;
- «Напоминай каждый вторник в 10 про планёрку» → повторяющееся напоминание;
- «Напомни сдать отчёт в пятницу, и напоминай, пока не сделаю» → после
  первого напоминания будет повторять раз в сутки, пока не нажмёте ✅;
- задача со сроком получает напоминание автоматически — отдельно просить
  не нужно; ✅ на таком напоминании закрывает и саму задачу;
- «⏰ Позже» без слов переносит на 3 часа (`modules.reminders.snooze_minutes`),
  словами можно точнее: «перенеси напоминание про отчёт на завтра».

Каждое утро в 08:30 приходит **сводка**: задачи на сегодня, просроченные,
напоминания дня. Время и отключение — `modules.reminders.morning_brief`.

Надёжность: напоминания хранятся в `data/sba.db` и переживают перезапуски —
если компьютер был выключен в назначенный момент, напоминание придёт после
запуска с пометкой об опоздании (утренняя сводка в этом случае приходит,
только пока она ещё актуальна — до 4 часов опоздания). Дубли после сбоев
отсекаются журналом доставки. Команда `/reminders` — предстоящие напоминания
без модели. Отключение модуля: `modules.reminders.enabled: false`.

Ограничение: ассистент напоминает, но само действие (письмо, звонок) не
выполняет — это по-прежнему делаете вы.

## Задачи (Sprint 5)

Полноценный список дел — говорите естественно:

- «Создай задачу позвонить Ивану завтра в 15:00» → задача со сроком;
- «Каждый понедельник — поливать цветы» → повторяющаяся задача: после
  «сделано» срок сам сдвигается на следующий понедельник;
- «Что у меня по проекту Экспедиция?» / «какие у меня задачи?» → список;
- «Отметь сделанным звонок Ивану», «перенеси отчёт на пятницу»,
  «отмени задачу про гараж» — изменения по названию или id (#a1b2c3).

Сроки понимаются по-русски: «завтра в 9», «через 2 часа», «в пятницу
вечером», «25 декабря», «по будням», «каждый месяц» — быстро и без модели;
хитрые формулировки разбирает маленькая LLM (роль `extraction`) со строгой
проверкой. Если срок неоднозначен («в понедельник» — в этот или следующий?),
ассистент уточнит, а не будет угадывать. Часовой пояс — `app.timezone`
(по умолчанию Москва).

Полезное: команда `/tasks` — открытые задачи по срокам (работает мгновенно,
без модели). Задачи хранятся в `data/sba.db` и переживают перезапуски.
Задачи со сроком с Sprint 6 сами напоминают о себе (см. раздел выше).
Отключение модуля: `modules.tasks.enabled: false`.

## Поиск по документам (Sprint 4)

Ассистент индексирует ваши папки и отвечает на вопросы по содержимому
PDF / DOCX / MD / TXT с указанием файла и места («найди в моих документах…»).

Настройка (один раз):

1. Скачайте эмбеддинг-модель (PowerShell): `ollama pull bge-m3`
2. В `config/local.yaml` укажите папки с документами (пути — в одинарных кавычках):

   ```yaml
   modules:
     rag:
       sources: ['C:\Users\имя\Documents', 'C:\Users\имя\Notes']
   ```

3. Перезапустите ассистента. Индексация идёт в фоне: новые и изменённые файлы
   подхватываются раз в 2 минуты, во время диалога индексатор ждёт паузы.

Полезное: команда `/rag` — состояние индекса; `python scripts\reindex.py` —
доиндексировать вручную, `--full` — перестроить с нуля (при остановленном
ассистенте). Память (Sprint 3) тоже использует семантический поиск: «вспомни
про собаку» найдёт факт про пса. Если Ollama выключена или bge-m3 не скачана,
поиск и память продолжают работать в лексическом режиме (по словам).

## Память (Sprint 3)

Ассистент помнит между перезапусками. Говорите естественно:

- «Запомни: Иван Петров — подрядчик по смете» → факт в памяти (тип: человек);
- «Запомни предпочтение: отвечай кратко» → влияет на все будущие ответы;
- «Что ты знаешь об Иване?» → поиск по памяти (русская морфология учитывается);
- «Забудь про старый пароль» → мягкое удаление (физически восстановимо в БД).

Релевантные факты автоматически подмешиваются в контекст ответа; предпочтения —
всегда в системном промпте. Факты не перезаписываются: противоречащее
предпочтение вытесняет старое с сохранением истории. Отключение модуля:
`modules.memory.enabled: false`.

## Инструменты ассистента (Sprint 2)

Ассистент сам решает, когда позвать инструмент: `get_current_time`, `list_files`,
`read_document` (текстовые файлы), `delete_file` (в корзину, **только после
подтверждения** — ответьте «да» или «нет» на вопрос ассистента).

Файловые инструменты работают строго внутри разрешённых папок. Добавьте их
в `config/local.yaml` (Windows-пути — в одинарных кавычках):

```yaml
files:
  allowed_roots: ['C:\Users\имя\Downloads', 'C:\Users\имя\Documents']
```

Каждый вызов инструмента записывается в журнал действий (таблица `audit_log`
в `data/sba.db`). Модели без нативного tool calling поддерживаются через
JSON-fallback: `tool_mode: json` у роли в `config/models.yaml`.

## Запуск (разработка)

```bash
# один раз: окружение
uv venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
uv pip install -e ".[dev]"

# консольный канал: диалог с локальной LLM (нужна запущенная Ollama)
python -m sba

# проверки — те же, что в CI
ruff check . && mypy && lint-imports && pytest -q
```

Настройки: `config/default.yaml` (в git) переопределяются файлом `config/local.yaml`
(не в git) и переменными окружения вида `SBA__LOGGING__LEVEL=DEBUG`.
Роли моделей — в `config/models.yaml`; диагностический режим без LLM:
`SBA__AGENT__PROCESSOR=echo`.

При старте ассистент прогревает модель (загружает её в RAM) до приёма сообщений
— в логе видно `model_warming_up` → `model_ready`. На CPU это занимает минуты,
и в это время бот сознательно молчит: зато первый вопрос отвечается сразу, а не
падает по таймауту. Отключить прогрев: `llm.keep_warm_minutes: 0`.

## Подключение Telegram

1. Создайте бота: в Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` →
   получите токен.
2. Создайте `config/local.yaml` (файл не попадает в git):

   ```yaml
   channels:
     telegram:
       enabled: true
       token: "СЮДА_ТОКЕН_ОТ_BOTFATHER"
       allowed_user_ids: []   # пока пусто — см. шаг 3
   ```

3. Запустите `python -m sba` и напишите боту любое сообщение. Бот промолчит,
   а в логе появится строка `telegram_unauthorized` с вашим числовым `user_id` —
   впишите его в `allowed_user_ids: [ваш_id]` и перезапустите. Сообщения от всех
   остальных игнорируются молча.

## Автозапуск (сервис-режим)

- **Windows:** `powershell -ExecutionPolicy Bypass -File scripts\install_autostart_windows.ps1` —
  регистрирует задачу планировщика: старт при входе в систему, авто-перезапуск при
  падении, лог в `data\service.log`.
- **Linux:** `scripts/sba.service` — systemd unit (инструкция внутри файла).
