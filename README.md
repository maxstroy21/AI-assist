# Second Brain Agent — персональный локальный AI-ассистент

Полностью локальный AI-ассистент: «операционная система знаний» одного человека.
Знает ваши документы, помнит контекст, управляет задачами и напоминаниями,
доступен через Telegram и локальные интерфейсы, работает на локальной LLM.

> Этот репозиторий сейчас находится на стадии **архитектурного проектирования**.
> Код появится только после согласования архитектуры (см. принцип «сначала
> проектирование, потом реализация»).

---

## Принципы

| # | Принцип | Что это значит на практике |
|---|---------|----------------------------|
| 1 | **Local First** | Все данные и вычисления — на вашей машине. Облако — опциональный плагин, а не зависимость. |
| 2 | **AI First** | Решения принимает LLM через tool calling. Мы не пишем «умную» бизнес-логику там, где её может выполнить модель. |
| 3 | **Modular** | Каждая способность — отдельный модуль, который можно включить/выключить в конфиге. |
| 4 | **Expandable** | Новые инструменты, источники данных, модели, агенты и каналы общения добавляются без переписывания ядра. |
| 5 | **Agentic** | Ассистент сам выбирает инструменты и планирует шаги, а не просто отвечает текстом. |

## Ключевые архитектурные решения (кратко)

| Область | Решение | Почему (подробно — в документах) |
|---------|---------|----------------------------------|
| Общая архитектура | **Модульный монолит** с внутренней событийной шиной и плагинами | Один процесс проще эксплуатировать на личной машине; модульность даёт расширяемость микросервисов без их операционной цены |
| LLM | Любой рантайм через **OpenAI-совместимый API** (Ollama, LM Studio, llama.cpp-server, vLLM, Jan…) | Рантайм — строка в конфиге, не архитектурное решение |
| Векторное хранилище | **Qdrant** (локальный, embedded-режим для старта) | Гибридный поиск, фильтры по метаданным, снапшоты; сравнение 6 вариантов — в [docs/02-architecture.md](docs/02-architecture.md) |
| Реляционные данные | **SQLite (WAL)** — задачи, память, метаданные, журнал | Нулевая эксплуатация, простой бэкап, достаточно для одного пользователя |
| Инструменты | Единый **Tool Registry** + **MCP** как протокол подключения внешних инструментов | Внутренние тулзы — in-process; внешние и сторонние — через MCP |
| Telegram | **aiogram 3**, long polling | Не нужен публичный IP — соответствует Local First |
| Голос | **faster-whisper** локально | Транскрипция голосовых без облака |
| Планировщик | **APScheduler** + SQLite job store | Переживает перезапуски, лёгкий |
| Язык/стек | Python 3.12, asyncio, Pydantic v2 | Экосистема AI-инструментов, типизация контрактов |

## Web-чат (Sprint 9)

Второй канал: чат в браузере на этой же машине. Работает одновременно
с Telegram — напоминания приходят в оба канала, у каждого канала своя история.
Внутри — то же ядро: streaming ответа, маркеры вызова инструментов 🔧, кнопки
✅/⏰/✖ у напоминаний, команды `/tasks`, `/memory`, `/new` и т.д.

Включение — две строки в `config/local.yaml`:

```yaml
channels:
  web:
    enabled: true
```

После запуска `python -m sba` в консоли появится строка
`🌐 Web-чат: http://127.0.0.1:8765` — откройте этот адрес в браузере.

Безопасность: чат слушает только `127.0.0.1` — с других компьютеров он
недоступен, поэтому пароля нет. Не меняйте `host` на другой адрес, если не
понимаете последствий (исключение — Tailscale-доступ с телефона, см. backlog).

## MCP (Sprint 9)

[MCP](https://modelcontextprotocol.io) — открытый протокол инструментов для
AI-ассистентов. Подключён в обе стороны (ADR-7).

### Чужие инструменты — нашему ассистенту

Готовые MCP-серверы (git, скачивание страниц, календари…) подключаются
конфигом — без единой строки кода. Их инструменты появляются у ассистента
наравне со встроенными: виден маркер 🔧, вызовы пишутся в `/audit`, действует
та же модель риска. По умолчанию риск — `destructive` (каждый вызов требует
подтверждения «да»); если сервер безобиден, понизьте риск осознанно:

```yaml
mcp:
  servers:
    - name: fetch              # скачивание страниц = простой web-доступ
      command: uvx             # нужен установленный uv (winget install astral-sh.uv)
      args: [mcp-server-fetch]
      risk: read
```

Недоступный сервер не мешает запуску: подключение идёт в фоне, каналы
отвечают с первой секунды, а в логе появляется `mcp_server_unavailable`
(и хаб продолжает пытаться подключиться). При падении уже подключённого
сервера хаб переподключается сам. Чтобы временно отключить конкретный
сервер, не удаляя его настройку, допишите ему строку `enabled: false`.

### Наш «мозг» — другим ассистентам (Claude Desktop)

Отдельный процесс `python -m sba.mcp.server` отдаёт инструменты ассистента
(поиск по документам, память, задачи — список: `mcp.export_modules`) любому
MCP-клиенту. Опасные (destructive) инструменты не экспортируются никогда.

Подключение к Claude Desktop:

1. Откройте PowerShell в папке проекта и выполните целиком:

```powershell
$repo = (Get-Location).Path
$cfgDir = "$env:APPDATA\Claude"
New-Item -ItemType Directory -Force -Path $cfgDir | Out-Null
$cfgPath = "$cfgDir\claude_desktop_config.json"
$cfg = if (Test-Path $cfgPath) { Get-Content $cfgPath -Raw | ConvertFrom-Json } else { [pscustomobject]@{} }
if (-not $cfg.PSObject.Properties['mcpServers']) { $cfg | Add-Member mcpServers ([pscustomobject]@{}) }
$server = [pscustomobject]@{ command = "$repo\.venv\Scripts\python.exe"; args = @('-m','sba.mcp.server','--config-dir',"$repo\config") }
if ($cfg.mcpServers.PSObject.Properties['second-brain']) { $cfg.mcpServers.'second-brain' = $server } else { $cfg.mcpServers | Add-Member 'second-brain' $server }
$cfg | ConvertTo-Json -Depth 10 | Set-Content $cfgPath -Encoding UTF8
Write-Host "Готово: $cfgPath"
```

2. Полностью перезапустите Claude Desktop (значок в трее → Quit).

3. В новом чате Claude Desktop нажмите иконку инструментов — в списке должен
   появиться сервер `second-brain` с инструментами `search_documents`,
   `recall_memory`, `create_task` и другими. Спросите: «что лежит у меня
   в памяти про кофе?» — Claude вызовет `recall_memory`.

Особенности:

- SQLite общий с основным ассистентом: задача, созданная из Claude Desktop,
  видна в `/tasks` в Telegram (и наоборот).
- Если основное приложение запущено, векторный индекс занят им — поиск по
  документам из Claude Desktop работает по словам (FTS), это штатно.
- Все вызовы пишутся в тот же журнал `/audit`.

## Файловые операции (Sprint 8, режим проверки)

Ассистент умеет наводить порядок в файлах — переместить, скопировать,
переименовать, убрать в архив, найти дубликаты и старые версии:

- «Перемести отчёт.docx в папку Документы», «переименуй файл в план-2026.docx»;
- «Убери из Downloads в архив всё старше 30 дней» — файлы уедут в подпапку
  `_архив` той же папки (имя — `modules.fileops.archive_subdir`);
- «Найди дубликаты в Downloads» — побайтово одинаковые файлы и сколько места
  они съедают; «найди старые версии» — группы вида `отчёт_v2`, `отчёт (1)`,
  `отчёт - копия` с указанием самой свежей;
- «Отмени последнюю операцию» — откат последней выполненной операции
  (перемещения возвращаются на место, созданная копия уходит в корзину).

**Сейчас включён режим сухого прогона**: операции только планируются —
ассистент показывает план («что бы я сделал»), но файлы НЕ меняются. Это
защитный режим первой недели самого рискованного функционала. Проверить
режим и журнал операций: команда `/fileops`. Когда планы подтвердят свою
адекватность, реальное исполнение включается строкой в `config/local.yaml`:

```yaml
modules:
  fileops:
    execute: true
```

Правила безопасности (в любом режиме): работа только внутри разрешённых папок
(`files.allowed_roots`), перезапись существующих файлов запрещена всегда,
каждая операция журналируется и обратима через undo.

## Напоминания (Sprint 6)

Ассистент теперь сам пишет вам вовремя — в Telegram и в консоль:

- «Напомни завтра в 15:00 позвонить Ивану» → в 15:00 придёт сообщение
  с кнопками **✅ Сделал / ⏰ Позже / ✖ Отменить**;
- «Напоминай каждый вторник в 10 про планёрку» → повторяющееся напоминание;
- «Напомни сдать отчёт в пятницу, и напоминай, пока не сделаю» → после
  первого напоминания будет повторять раз в сутки, пока не нажмёте ✅;
- задача со сроком получает напоминание автоматически — отдельно просить
  не нужно; ✅ на таком напоминании закрывает и саму задачу;
- «⏰ Позже» без слов переносит на 3 часа (`modules.reminders.snooze_minutes`),
  словами можно точнее: «перенеси напоминание про отчёт на завтра».

Каждое утро в 08:30 приходит **сводка**: задачи на сегодня, просроченные,
напоминания дня. Время и отключение — `modules.reminders.morning_brief`.

Надёжность: напоминания хранятся в `data/sba.db` и переживают перезапуски —
если компьютер был выключен в назначенный момент, напоминание придёт после
запуска с пометкой об опоздании (утренняя сводка в этом случае приходит,
только пока она ещё актуальна — до 4 часов опоздания). Дубли после сбоев
отсекаются журналом доставки. Команда `/reminders` — предстоящие напоминания
без модели. Отключение модуля: `modules.reminders.enabled: false`.

Ограничение: ассистент напоминает, но само действие (письмо, звонок) не
выполняет — это по-прежнему делаете вы.

## Задачи (Sprint 5)

Полноценный список дел — говорите естественно:

- «Создай задачу позвонить Ивану завтра в 15:00» → задача со сроком;
- «Каждый понедельник — поливать цветы» → повторяющаяся задача: после
  «сделано» срок сам сдвигается на следующий понедельник;
- «Что у меня по проекту Экспедиция?» / «какие у меня задачи?» → список;
- «Отметь сделанным звонок Ивану», «перенеси отчёт на пятницу»,
  «отмени задачу про гараж» — изменения по названию или id (#a1b2c3).

Сроки понимаются по-русски: «завтра в 9», «через 2 часа», «в пятницу
вечером», «25 декабря», «по будням», «каждый месяц» — быстро и без модели;
хитрые формулировки разбирает маленькая LLM (роль `extraction`) со строгой
проверкой. Если срок неоднозначен («в понедельник» — в этот или следующий?),
ассистент уточнит, а не будет угадывать. Часовой пояс — `app.timezone`
(по умолчанию Москва).

Полезное: команда `/tasks` — открытые задачи по срокам (работает мгновенно,
без модели). Задачи хранятся в `data/sba.db` и переживают перезапуски.
Задачи со сроком с Sprint 6 сами напоминают о себе (см. раздел выше).
Отключение модуля: `modules.tasks.enabled: false`.

## Поиск по документам (Sprint 4)

Ассистент индексирует ваши папки и отвечает на вопросы по содержимому
PDF / DOCX / MD / TXT с указанием файла и места («найди в моих документах…»).

Настройка (один раз):

1. Скачайте эмбеддинг-модель (PowerShell): `ollama pull bge-m3`
2. В `config/local.yaml` укажите папки с документами (пути — в одинарных кавычках):

   ```yaml
   modules:
     rag:
       sources: ['C:\Users\имя\Documents', 'C:\Users\имя\Notes']
   ```

3. Перезапустите ассистента. Индексация идёт в фоне: новые и изменённые файлы
   подхватываются раз в 2 минуты, во время диалога индексатор ждёт паузы.

Полезное: команда `/rag` — состояние индекса; `python scripts\reindex.py` —
доиндексировать вручную, `--full` — перестроить с нуля (при остановленном
ассистенте). Память (Sprint 3) тоже использует семантический поиск: «вспомни
про собаку» найдёт факт про пса. Если Ollama выключена или bge-m3 не скачана,
поиск и память продолжают работать в лексическом режиме (по словам).

## Память (Sprint 3 + Sprint 7)

Ассистент помнит между перезапусками. Говорите естественно:

- «Запомни: Иван Петров — подрядчик по смете» → факт в памяти (тип: человек);
- «Запомни предпочтение: отвечай кратко» → влияет на все будущие ответы;
- «Что ты знаешь об Иване?» → поиск по памяти (русская морфология учитывается);
- «О чём мы говорили про экспедицию?» → найдутся итоги прошлых разговоров;
- «Забудь про старый пароль» → мягкое удаление (физически восстановимо в БД).

Релевантные факты автоматически подмешиваются в контекст ответа; предпочтения —
всегда в системном промпте. Факты не перезаписываются: противоречащее
предпочтение или решение вытесняет старое с сохранением истории («ранее
решали иначе» видно в ответе). Отключение модуля: `modules.memory.enabled: false`.

**Автопамять (Sprint 7).** Память пополняется и сама: когда разговор
заканчивается (час тишины или /new), ассистент в фоне сворачивает его в
«эпизод» (краткий итог: о чём говорили, темы, проект) и выписывает из него
устойчивые факты — имена, проекты, решения. Работает это только в паузах,
чтобы не замедлять ответы, и намеренно консервативно:

- факты с низкой уверенностью отбрасываются (`modules.memory.min_confidence`);
- с одного разговора — не больше 5 записей, дубликаты не плодятся;
- предпочтения автоматически НЕ извлекаются — поведение ассистента меняет
  только явное «запомни»;
- команда `/memory` показывает, что запомнилось за неделю (🤖 — автозапись,
  ✍️ — явная), лишнее убирается словами «забудь …».

Отключить автопамять: `modules.memory.auto_extract: false` в `config/local.yaml`.

**Ускорение ответов на слабой машине.** На CPU без видеокарты почти всё время
ответа уходит не на генерацию, а на «переваривание» промпта — а самое тяжёлое в
нём это схемы всех инструментов, которые по умолчанию шлются модели на каждое
сообщение. Включите отправку только нужных под тему инструментов — в
`config/local.yaml`:

```yaml
agent:
  topic_scoped_tools: true
```

Тогда на файловый вопрос идут только файловые инструменты, на вопрос про задачи —
задачные, а на общую реплику («привет») — вообще никакие. Промпт короче в разы,
ответ на CPU заметно быстрее, и слабая модель реже путается в выборе инструмента.

**Экономия памяти на слабой машине.** По умолчанию память ищет по смыслу и ради
этого держит модель bge-m3 в RAM почти постоянно (~1.2 ГБ). Если оперативной
памяти в обрез, переключите память на поиск по словам — в `config/local.yaml`:

```yaml
modules:
  memory:
    semantic: false
```

Тогда bge-m3 грузится только под поиск по документам, а не постоянно; освобождается
~1.2 ГБ и пропадает конкуренция за CPU между моделями. Размен: «вспомни про пса»
уже не найдёт факт, записанный про «собаку», — совпадение идёт по словам, как в
поиске задач. Поиск по документам (Sprint 4) при этом работает как прежде.

## Облачная модель Claude вместо локальной (по желанию)

По умолчанию ассистент разговаривает локальной моделью (Ollama, на вашем CPU) —
приватно и без интернета. При желании роль диалога (`chat`) можно перевести на
облачный Claude: ответы станут заметно умнее и быстрее, но текст сообщений и
имена файлов будут уходить на серверы Anthropic (локальность теряется).

Вход — **под вашим аккаунтом Claude** (без отдельного платного API-ключа).
Честно: использовать подписочный вход для постоянно работающего бота — серая
зона по условиям Anthropic, и раз в какое-то время вход придётся обновлять.

Настройка (один раз, PowerShell):

1. Установите Anthropic CLI (страница релизов `github.com/anthropics/anthropic-cli`)
   и войдите под своим аккаунтом (откроется браузер):

   ```
   ant auth login
   ```

2. Установите пакет Claude в окружение ассистента:

   ```
   .\.venv\Scripts\Activate.ps1; pip install anthropic
   ```

3. В `config/models.yaml` раскомментируйте рантайм `anthropic` и переназначьте на
   него роль `chat` (пример уже есть в файле). Роль `embedding` **оставьте на
   ollama** — у Anthropic нет эмбеддингов, на них держится поиск по документам.

4. В `config/local.yaml` выключите прогрев (облаку он не нужен):

   ```yaml
   llm:
     keep_warm_minutes: 0
   ```

5. Перезапустите ассистента. Ключ в `config/models.yaml` писать **не нужно** —
   файл в git; авторизацию SDK берёт из вашего входа `ant auth login`.

Вернуться к локальной модели — просто верните роль `chat` на `ollama`. Если вместо
входа под аккаунтом удобнее ключ API — задайте его переменной окружения
`ANTHROPIC_API_KEY`, остальное работает так же.

### DeepSeek и другие OpenAI-совместимые облака

Если Claude недоступен (Anthropic закрыт в вашем регионе), подойдёт любой
OpenAI-совместимый облачный провайдер — например **DeepSeek** (дешёвый, доступен
шире). Отдельный код не нужен: это тот же `openai_compatible`-рантайм, что и Ollama.

1. Создайте ключ на `platform.deepseek.com` (раздел API Keys) и пополните баланс
   (Top up). Ключ показывается один раз — сохраните.
2. Пропишите ключ в переменную окружения (PowerShell, ключ вставляете вы, в git
   он не попадает), затем **перезапустите PowerShell**:

   ```
   setx DEEPSEEK_API_KEY "sk-ваш-ключ"
   ```

3. В `config/models.yaml` раскомментируйте рантайм `deepseek` и переназначьте на
   него роль `chat` (примеры уже в файле). В файле стоит `${DEEPSEEK_API_KEY}` —
   реальный ключ подставится из окружения, сам ключ в git не хранится.
4. Роль `embedding` оставьте на `ollama` (у DeepSeek эмбеддингов нет).
5. Перезапустите ассистента.

Тот же приём работает для любого другого OpenAI-совместимого сервиса — меняются
только `base_url`, `model` и имя переменной с ключом.

## Инструменты ассистента (Sprint 2)

Ассистент сам решает, когда позвать инструмент: `get_current_time`, `list_files`,
`read_document` (текстовые файлы), `delete_file` (в корзину, **только после
подтверждения** — ответьте «да» или «нет» на вопрос ассистента).

Файловые инструменты работают строго внутри разрешённых папок. Добавьте их
в `config/local.yaml` (Windows-пути — в одинарных кавычках):

```yaml
files:
  allowed_roots: ['C:\Users\имя\Downloads', 'C:\Users\имя\Documents']
```

Каждый вызов инструмента записывается в журнал действий (таблица `audit_log`
в `data/sba.db`). Модели без нативного tool calling поддерживаются через
JSON-fallback: `tool_mode: json` у роли в `config/models.yaml`.

## Запуск (разработка)

```bash
# один раз: окружение
uv venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
uv pip install -e ".[dev]"

# консольный канал: диалог с локальной LLM (нужна запущенная Ollama)
python -m sba

# проверки — те же, что в CI
ruff check . && mypy && lint-imports && pytest -q
```

Настройки: `config/default.yaml` (в git) переопределяются файлом `config/local.yaml`
(не в git) и переменными окружения вида `SBA__LOGGING__LEVEL=DEBUG`.
Роли моделей — в `config/models.yaml`; диагностический режим без LLM:
`SBA__AGENT__PROCESSOR=echo`.

При старте ассистент прогревает модель (загружает её в RAM) до приёма сообщений
— в логе видно `model_warming_up` → `model_ready`. На CPU это занимает минуты,
и в это время бот сознательно молчит: зато первый вопрос отвечается сразу, а не
падает по таймауту. Отключить прогрев: `llm.keep_warm_minutes: 0`.

## Подключение Telegram

1. Создайте бота: в Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` →
   получите токен.
2. Создайте `config/local.yaml` (файл не попадает в git):

   ```yaml
   channels:
     telegram:
       enabled: true
       token: "СЮДА_ТОКЕН_ОТ_BOTFATHER"
       allowed_user_ids: []   # пока пусто — см. шаг 3
   ```

3. Запустите `python -m sba` и напишите боту любое сообщение. Бот промолчит,
   а в логе появится строка `telegram_unauthorized` с вашим числовым `user_id` —
   впишите его в `allowed_user_ids: [ваш_id]` и перезапустите. Сообщения от всех
   остальных игнорируются молча.

## Автозапуск (сервис-режим)

- **Windows:** `powershell -ExecutionPolicy Bypass -File scripts\install_autostart_windows.ps1` —
  регистрирует задачу планировщика: старт при входе в систему, авто-перезапуск при
  падении, лог в `data\service.log`.
- **Linux:** `scripts/sba.service` — systemd unit (инструкция внутри файла).
